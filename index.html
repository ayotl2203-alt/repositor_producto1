2. Marco teórico

2.1 Bases de datos relacionales, SQL y PostgreSQL

Una base de datos relacional organiza la información en tablas relacionadas mediante llaves, y SQL es el lenguaje con el que se definen, insertan y consultan esos datos. PostgreSQL es un sistema de gestión de bases de datos relacional de código abierto que incluye restricciones de llave primaria y foránea para mantener la integridad de los datos (PostgreSQL Global Development Group, 2026a, 2026e). Su relación con las prácticas es directa: las Actividades 2 y 4 trabajan con tablas, relaciones y consultas SQL.

2.2 psql y pg_dump

psql es la terminal interactiva de PostgreSQL; permite ejecutar SQL y meta-comandos como \dt o \du (PostgreSQL Global Development Group, 2026f). Por su parte, pg_dump extrae una base de datos en un archivo de respaldo (PostgreSQL Global Development Group, 2026b). psql se utiliza principalmente en la Actividad 4 y en la administración de usuarios de la Actividad 5, mientras que pg_dump se emplea en las aplicaciones de respaldo de la Actividad 5.

2.3 Roles, privilegios y seguridad

En PostgreSQL los usuarios son roles con permiso de inicio de sesión, y cada objeto tiene un propietario que debe otorgar privilegios a los demás roles (PostgreSQL Global Development Group, 2026c). El comando GRANT asigna esos privilegios (PostgreSQL Global Development Group, 2026d). Neon adopta este modelo de roles (Neon, 2024). Aplicar el principio de mínimo privilegio, como en la Actividad 5, reduce el riesgo de modificaciones no autorizadas.

2.3.1 Bases de datos en la nube y Neon

Neon es un servicio de PostgreSQL en la nube que ofrece conexión remota mediante una cadena de conexión y un editor SQL en el navegador (Neon, 2026). Permitió trabajar sin instalar un servidor propio, tanto desde psql como desde código.

2.4 Modelo cliente-servidor y aplicaciones web

En una aplicación web el navegador (cliente) envía peticiones HTTP a un servidor, que responde con HTML, JSON u otros recursos; el contenido se estructura y presenta según la tecnología utilizada (Mozilla, 2026). Las Actividades 2, 3 y 5 aplican este modelo y además se conectan a la base de datos remota.

2.5 PHP, Composer y Laminas DB

PHP es un lenguaje de programación del lado del servidor muy usado en aplicaciones web (PHP Group, 2026). Composer administra las dependencias de un proyecto PHP (Composer, 2026) y Laminas DB es un componente que ofrece un adaptador para conectarse a bases de datos (Laminas Project, 2026). Se instalaron en la Actividad 1 y se aplicaron en la Actividad 2.

2.6 .NET y ASP.NET Core

.NET es la plataforma de desarrollo de Microsoft; ASP.NET Core permite crear aplicaciones web con C# (Microsoft, 2026). En la Actividad 3 se utilizó para construir el endpoint JSON y también aparece como una de las aplicaciones de respaldo de la Actividad 5.

2.7 Go, Python con Flask y Rust con Axum

Go es un lenguaje compilado con biblioteca estándar para servidores HTTP (Go Project, 2026). Flask es un microframework web de Python (Pallets, 2026). Rust es un lenguaje de sistemas que se gestiona con Cargo, y Axum es un framework web para Rust (Rust Project Developers, 2026; Tokio Project, 2026). Con ellos se construyeron las aplicaciones 3, 4 y 5 de la Actividad 5.

CREATE TABLE asistencia(
    idmateria INT NOT NULL,
    idgrupo INT NOT NULL,
    idprofesor INT NOT NULL,
    idalumno INT NOT NULL,
    fecha DATE NOT NULL,
    valor_asistencia VARCHAR(10) NOT NULL,

    PRIMARY KEY (
        idmateria,
        idgrupo,
        idprofesor,
        idalumno,
        fecha

    FOREIGN KEY (idmateria)

Consulta INNER JOIN para mostrar información completa

SELECT
    al.nombre AS alumno,
    a.fecha,
    a.valor_asistencia AS asistencia,
    m.nombre AS materia,
    g.nombre AS grupo,
    p.nombre AS profesor
FROM asistencia a
INNER JOIN alumnos al
    ON a.idalumno = al.idalumno
INNER JOIN materia m
    ON a.idmateria = m.idmateria
INNER JOIN grupo g
    ON a.idgrupo = g.idgrupo
INNER JOIN profesor p
    ON a.idprofesor = p.idprofesor
ORDER BY al.nombre, a.fecha;

Se utilizaron alias para hacer la consulta más corta: a para asistencia, al para alumnos, m para materia, g para grupo y p para profesor. Cada INNER JOIN reemplaza un identificador por la información legible de la tabla relacionada.

Creación de la vista lista_asistencia_7e

Aunque SELECT * FROM asistencia; es correcto, su salida no se parece visualmente a la lista del profesor. Para presentar los datos con un alumno por fila y una columna por día se creó una vista:

CREATE OR REPLACE VIEW lista_asistencia_7e AS
SELECT
    al.idalumno,
    al.nombre AS alumno,

    COALESCE(MAX(CASE WHEN a.fecha = '2026-09-01'
        THEN a.valor_asistencia END), '') AS "1",
    COALESCE(MAX(CASE WHEN a.fecha = '2026-09-02'
        THEN a.valor_asistencia END), '') AS "2",
    COALESCE(MAX(CASE WHEN a.fecha = '2026-09-04'
        THEN a.valor_asistencia END), '') AS "4",
    COALESCE(MAX(CASE WHEN a.fecha = '2026-09-07'
        THEN a.valor_asistencia END), '') AS "7",
    COALESCE(MAX(CASE WHEN a.fecha = '2026-09-08'
        THEN a.valor_asistencia END), '') AS "8",
    COALESCE(MAX(CASE WHEN a.fecha = '2026-09-09'
        THEN a.valor_asistencia END), '') AS "9",
    COALESCE(MAX(CASE WHEN a.fecha = '2026-09-14'
        THEN a.valor_asistencia END), '') AS "14",
    COALESCE(MAX(CASE WHEN a.fecha = '2026-09-18'
        THEN a.valor_asistencia END), '') AS "18"

FROM alumnos al
LEFT JOIN asistencia a
    ON al.idalumno = a.idalumno
    AND a.idmateria = 6
    AND a.idgrupo = 1
    AND a.idprofesor = 6
GROUP BY al.idalumno, al.nombre
ORDER BY al.idalumno;
